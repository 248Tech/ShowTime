# Architecture

ShowTime is deliberately small: plain Node.js (ESM), the built-in `node:sqlite`, and a vanilla-JS single-page front-end. The only runtime dependency is `nodemailer`. FFmpeg does media work.

```
browser (SPA, vanilla JS)  ──HTTP/JSON──►  server.js  ──►  lib/*  ──►  SQLite (data/showtime.db)
        ▲   ▲                                  │                       └─ encrypted vault (data/vault/*.enc)
        │   └── Server-Sent Events ◄───────────┘
        └────── WebRTC (P2P local-file streaming, live subtitles) ──► other browsers
```

## Modules

| File | Responsibility |
|---|---|
| `server.js` | HTTP server, routing table, auth/session handling, CSRF + security headers, static files |
| `lib/db.js` | Schema, tiny migrations, prepared-statement helpers, **access-control queries** (`canAccessMedia`, `canAccessRoom`) |
| `lib/vault.js` | Chunked AES-256-GCM storage. Per-file key = HKDF(master, salt); header is AAD; final chunk flagged to detect truncation. Range-seekable |
| `lib/media.js` | ffprobe/ffmpeg helpers, filename + metadata classification (movie/TV), thumbnails, subtitle extraction, media-signature sniffing, loopback decrypt server |
| `lib/encode.js` | **Codec scan**: trial encodes → pure `decide()` → background AV1/VP9/H.264 encodes; encoder registry (incl. an inactive AV2 slot) |
| `lib/rooms.js` | In-memory room state machine, per-viewer snapshots, permissions, WebRTC signalling relay |
| `lib/presence.js` | Global event stream: friends online, invites, achievements |
| `lib/social.js` | **Privacy model**: friend codes, requests, blocks, aliases, `viewOf()` (what viewer X may know about user Y) |
| `lib/chat.js` | E2E-encrypted ephemeral chat: ciphertext only, RAM only, scheduled wipe |
| `lib/iptv.js` | Live TV directory, M3U import, health checks (incl. "is the playlist advancing?"), SSRF-guarded HLS proxy with session self-healing |
| `lib/stats.js` · `lib/achievements.js` · `lib/profile.js` | Server-side watch-time crediting, 30 badges, profile data |
| `lib/security.js` · `lib/avatar.js` · `lib/compliance.js` | scrypt/limits/mail · avatar re-encoding · copyright-tooling hook (no-op for now) |
| `public/` | The SPA (`app.js`), encrypted-chat UI (`chat.js`) and its shared crypto (`chatcrypto.js`), styles, vendored hls.js |

## Key design decisions

- **One place decides access.** Every media, thumbnail, subtitle, rendition and avatar request goes through the same ACL helpers; there are no public links.
- **Time is credited server-side.** The watch tracker only counts time while the user is attached to a room that is actually playing (so badges can't be faked from the browser).
- **Privacy is structural, not cosmetic.** The server never sends a stranger's real name, username, avatar or online status; `viewOf()` returns an alias. Rooms and invites are personalised per recipient.
- **The chat server is blind.** Keys are derived in the browser; the server stores `{iv, ciphertext}` blobs in memory and zero-fills them on the 48-hour wipe. Nothing is logged or audited.
- **Codec choice is measured, not guessed.** Trial encodes on the host machine produce real speed/size numbers; a pure, unit-tested function turns them into a plan. The player then chooses per viewer using `MediaCapabilities`.
- **The proxy is the dangerous part, so it is paranoid.** Signed expiring tokens, DNS-time and redirect-time private-IP blocking, size caps, no cookies upstream.

## Tests

`npm test` runs six suites, each spinning up real servers and (where relevant) real FFmpeg:

| Suite | What it proves |
|---|---|
| `test/ssrf.mjs` | The proxy refuses every spelling of loopback/private/link-local addresses and never contacts a trap server |
| `test/codec.mjs` | The codec decision function across edge cases (slow encoders, HDR, un-playable sources, savings thresholds) |
| `test/achievements.mjs` | Badge thresholds, streak maths, the one-minute rule, profile privacy gating |
| `test/iptv-heal.mjs` | Expiring provider sessions are re-resolved transparently; frozen feeds are rejected by the health check |
| `test/smoke.mjs` | The whole HTTP API: auth, CSRF, encryption at rest, sharing ACLs, rooms, permissions, friends/aliases, avatars, subtitles, AV1/VP9 renditions, watch tracking |
| `test/chat.mjs` | Real end-to-end crypto, wrong-passphrase rejection, tamper detection, a disk scan proving no chat byte is persisted, and a real wipe |

## The live demo

GitHub Pages cannot run Node, so the demo (`scripts/build-site.mjs`) copies the **real, unmodified front-end** from `public/` and injects `demo-src/mock.js`, which replaces `fetch`, `EventSource` and media URLs with an in-browser fake backend. The chat in the demo uses the real crypto code; only the "server" and the other people are simulated. `demo-src/hls-stub.js` stands in for hls.js, and three small sample clips (H.264/AV1/VP9) are generated by `scripts/make-demo-media.mjs`.
